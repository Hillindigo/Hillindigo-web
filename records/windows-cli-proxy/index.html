先确认失败发生在哪里

代理问题常被混在一起处理：应用配置、环境变量、Windows 系统代理和本地代理软件可能同时影响请求。

推荐顺序

  1. 查看 HTTP_PROXY 与 HTTPS_PROXY；
  2. 检查 Windows 系统代理；
  3. 确认本地端口是否监听；
  4. 使用明确不经过代理的请求测试目标端点；
  5. 最后再修改应用配置。

为什么要分层

如果目标地址本身不可达，反复调整代理不会解决问题；如果 CLI 被永久环境变量强制代理，关闭图形界面中的代理开关也没有作用。

记录每一步的输入和输出，可以避免在不同网络层之间来回猜测。
