给 Agent 更少但更准确的上下文

上下文不是越多越好。围绕目标加载符号、调用链和约束，通常比把整个仓库交给 Agent 更有效。

问题不在模型看得不够多

大量无关文件会稀释真正重要的约束。Agent 需要的不是整个仓库，而是与当前问题直接相关的定义、调用者、被调用者和验证方式。

一个有效的上下文包

可以包含：

  1. 目标与验收标准；
  2. 当前实现的关键符号；
  3. 相关调用链；
  4. 不能破坏的约束；
  5. 可执行的验证命令。

逐步扩展

先给最小上下文，如果证据不足，再沿调用关系扩展。这个过程比一次读取大量文件更容易发现真正的边界。

精确的上下文不是信息摘要，而是完成当前决策所需的证据集合。
