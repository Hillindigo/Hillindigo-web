LEARNING NOTE · GIT / COMMIT

用完整功能决定 Git 提交边界

提交不应该跟着每一次小改动走，而应该在一个可验证、可描述、可回滚的功能完成时发生。

2026.07.125 MIN READIN-PROGRESS
LEARNING TOPICS
Git工程实践工作流

为什么小改一次就提交并不好

碎片化提交会把同一个功能的样式、逻辑和验证拆散。后来查看历史时，很难从单个提交理解它带来了什么完整价值。

更合适的边界

一个提交应当满足：

  • 功能可以独立描述；
  • 相关代码已经完成；
  • 构建或测试已经通过；
  • 需要时可以整体回滚。

提交前检查

确认变更范围
运行类型检查
运行构建
查看最终 diff
编写清楚的提交信息

修复与独立功能可以分别提交，但同一功能中的小样式调整不必人为拆开。
